## 上午：克隆出 node2 / node3（约 1.5h）

### 为什么要三台

从 W7 的 Ansible 到 W14 的 K8s，多机集群是刚需。现在把机器备好，后面随时可用。

### 克隆步骤（VMware）

1. 确保 rocky1 **已关机**（克隆必须关机状态）
2. 右键 rocky1 → **管理 → 克隆** → 下一步
3. 克隆源选"虚拟机中的当前状态"
4. 克隆类型选 **"链接克隆"**（Linked Clone）——只占几百 MB 磁盘，共享母盘；完整克隆要占 60G×3
   - **代价要懂**：链接克隆依赖母机磁盘文件，母机文件不能移动/删除。实验环境链接克隆是最优解；生产环境这样做就是事故（面试可以说出这层权衡）
5. 分别命名 `rocky2`、`rocky3`

### 克隆后必做的三件事（每台都要）

**坑点预警**：克隆机和母机**网卡 MAC 地址不同、机器 ID 相同**，直接抢 IP 或主机名冲突。逐台执行：

```bash
# ① 改主机名（rocky2 上执行；rocky3 同理改成 rocky3）
hostnamectl set-hostname rocky2
# 验证（开新终端或重新登录后提示符会变）
hostnamectl

# ② 重置机器 ID（否则 DHCP 服务器认为三台是同一台机器，发同一个 IP）
rm -f /etc/machine-id && systemd-machine-id-setup

# ③ 重连网卡拿新 IP
nmcli device disconnect ens160 && nmcli device connect ens160
ip addr    # 确认拿到 192.168.100.x，且和 rocky1 不同
```

### 三台互通验证（这是"集群"的最低标准）

```bash
# 在 rocky1 上 ping 另外两台（IP 换成实际值）
ping -c 3 192.168.100.xxx
ping -c 3 192.168.100.yyy
```

三台互 ping 全通 → **拍快照**（每台都拍，命名 `cluster-init`）。

### 建议顺手做：/etc/hosts 静态解析（三台都做）

```bash
cat >> /etc/hosts << 'EOF'
192.168.100.10  rocky1
192.168.100.11  rocky2
192.168.100.12  rocky3
EOF
# IP 按你实际分配的改！建议在虚拟网络编辑器里把 DHCP 范围设置好记的段
# 验证：ping rocky2 能通（用主机名而不是 IP）
ping -c 2 rocky2
```

> 为什么用 /etc/hosts：W7 的 Ansible inventory 直呼其名，W12 的 K8s 节点也要它。这是集群的第一块积木。

## 下午：软硬链接与 inode（约 2.5h，你摸底的空白区）

### 知识铺垫（先读 10 分钟，再动手）

**inode 是什么**：Linux 文件系统里，每个文件 = **inode（元数据）+ 数据块（内容）**。inode 存权限、属主、大小、时间戳、**指向数据块的指针**——注意：**文件名不在 inode 里**，文件名存在目录项里，目录项负责把"名字 → inode 号"映射起来。

由此推出核心结论：

| | 硬链接 | 软链接 |
|---|---|---|
| 本质 | 同一个 inode 的**第二个名字**（目录项多一条记录） | 独立文件，有自己的 inode，**内容是目标的路径** |
| 创建 | `ln 源 目标` | `ln -s 源 目标` |
| 删除源文件后 | 不受影响（inode 引用计数 > 0，数据还在） | **变悬空（dangling）**，访问报"No such file" |
| 跨文件系统 | ❌（inode 号只在自家文件系统内唯一） | ✅ |
| 链接目录 | ❌（root 也不建议，会造出环） | ✅ |
| 大小 | 与源相同（就是同一个文件） | 路径字符串的长度 |

### 实验 1：眼见为实（逐条敲，观察输出）

```bash
mkdir -p ~/labs/w01 && cd ~/labs/w01

# 1. 创建源文件，写入内容
echo "hello inode" > origin.txt

# 2. 分别创建硬链接和软链接
ln origin.txt hard.txt
ln -s origin.txt soft.txt

# 3. 关键一步：看三者的 inode 号（-i 选项）
ls -li
# 预期：origin.txt 和 hard.txt 的 inode 号【相同】，soft.txt【不同】且类型列是 l

# 4. 看软链接里装的是什么
cat soft.txt        # 输出 hello inode（间接读到）
readlink soft.txt   # 输出 origin.txt（它存的就是这个字符串）

# 5. 删除源文件，观察两个链接的命运
rm origin.txt

cat hard.txt    # ✅ 正常输出——inode 还活着，hard.txt 就是它
cat soft.txt    # ❌ No such file or directory——悬空了
ls -li          # 对比删除前后 hard.txt 的链接数变化（原为 2，现变 1）
```

**把第 3 步和第 5 步的输出截图存档**——面试被问到"删除源文件后软/硬链接分别怎样"，你答"我做过实验，硬链接的 inode 引用计数从 2 变 1，数据不受影响"比背概念有说服力一百倍。

### 实验 2：生产场景（软链接的真实用途）

```bash
# 场景：版本目录切换——生产发布回滚的底层原理
mkdir -p /opt/app/v1.0 /opt/app/v1.1
echo "version 1" > /opt/app/v1.1/index.html

ln -sfn /opt/app/v1.1 /opt/app/current
cat /opt/app/current/index.html    # version 1

# 模拟回滚：把 current 指回旧版本
echo "version 0" > /opt/app/v1.0/index.html
ln -sfn /opt/app/v1.0 /opt/app/current
cat /opt/app/current/index.html    # version 0 —— 秒级回滚！
```

`ln -sfn` 的 `-n` 是关键坑：没有它，对"指向目录的软链接"再 ln 会把链接建到目录**里面**去。把这条命令记进笔记。

### 实验 3：找出系统里的软链接在干嘛

```bash
ls -l /usr/bin | grep '^l' | head
# 你会看到大量系统命令是软链接，比如 python3 -> /usr/bin/python3.x
# 理解了它，就理解了"多版本共存、一个入口"的设计
```

## 下午后半：find 完整用法（约 1.5h）

你摸底时 `find /data/logs -mtime +7 -type f -name "*.log"` 写对了查找部分，缺**执行动作**。今天补齐：

### 核心语法骨架

```
find [路径] [条件] [动作]
```

### 条件大全（逐条敲一遍，用 /var/log 当靶场）

```bash
# 按名字（-name 支持通配符；-iname 忽略大小写）
find /var/log -name "*.log"
find /var/log -iname "*.LOG"          # 同样能搜到

# 按类型：f=文件 d=目录 l=软链接
find /etc -type l -name "*.conf"      # 找出是软链接的 conf
find /var/log -type d                 # 找目录

# 按时间（重点，单位都是"天"，面试爱考）
find /var/log -mtime +7               # 修改时间在 7 天【前】（+7 = 大于7天）
find /var/log -mtime -7               # 7 天【内】
find /var/log -mtime 7                # 恰好第 7 天（很少用，知道即可）
find /tmp -mmin -60                   # 60 分钟内修改过（-mmin 分钟版，排查"刚才谁动过文件"神器）

# 按大小（c=字节；不带单位=块=512B）
find /var/log -size +100M             # 大于 100M 的文件——磁盘告急时第一反应命令
find /var/log -size +10M -size -50M   # 10M~50M 之间（条件默认"与"关系）

# 取反（你摸底没答出来的 !）
find /var/log -name "*.log" ! -name "*gz"    # 是 .log 但不是压缩包

# 组合：找出大日志且排除已归档的
find /var/log -type f -size +50M ! -name "*.gz"
```

### 动作大全（补你摸底缺的那半）

```bash
# 动作一：-delete 直接删（简单场景）
find /tmp -name "*.tmp" -delete

# 动作二：-exec（通用，重点）
find /tmp -name "*.log" -exec rm -f {} \;
#    解释：{} 是占位符，代表 find 找到的每个文件；\; 是命令结束符（转义分号）

# 动作三：-exec + 批量模式（文件多时更快，一次传多个参数）
find /tmp -name "*.log" -exec rm -f {} +

# 动作四：先打印确认，再动手（生产安全习惯）
find /tmp -name "*.log" -print -delete

# 动作五：交给 xargs（与 | 管道的区别是你 W1 的面试题！）
find /tmp -name "*.log" | xargs rm -f
```

**`{} \;` 和 `{} +` 与 xargs 的区别**（面试高频，务必自己总结进笔记）：

| 方式 | 执行方式 | 类比 |
|---|---|---|
| `-exec {} \;` | 每个文件单独起一次命令 | 发 100 个快递，跑 100 趟 |
| `-exec {} +` | 尽量攒一批一起传 | 攒一车一起送 |
| `| xargs cmd` | 同上攒批，且 xargs 是通用工具 | 快递公司，谁都能用 |

### 靶场实战（今天的主实验）

```bash
# 1. 造靶场：批量生成 100 个文件，时间戳错开
mkdir -p /data/logs && cd /data/logs
for i in $(seq 1 100); do
  touch -d "2026-08-0$((RANDOM % 9 + 1))" app_$i.log
done

# 2. 任务 A：找出 30 天前的 .log（先看数量）
find /data/logs -type f -name "*.log" -mtime +30 | wc -l

# 3. 任务 B：打印确认后删除
find /data/logs -type f -name "*.log" -mtime +30 -print -delete

# 4. 任务 C：删除后验证
ls /data/logs | wc -l    # 数量对得上就闭环了
```
