## 理论基础（先读 40 分钟，再动手）

### 1. 变量与引用三剑客（昨晚已踩坑，今天系统学）

```bash
name="wangchen"          # 赋值：等号两边【不能有空格】
echo $name               # 使用：加 $
echo "${name}_ops"       # 边界不明时必须加花括号（否则 $name_ops 会被当变量名）
readonly PI=3.14         # 只读变量
unset name               # 删除变量
```

| 引用方式 | 效果 | 什么时候用 |
|---|---|---|
| `'单引号'` | **全部字面化** | 正则、密码、含 `!` `$` 的字符串（昨晚的坑） |
| `"双引号"` | 保留 `$` `!` `` ` `` 展开 | 需要变量拼接时 |
| `` `命令` `` 或 `$(命令)` | 命令替换 | `today=$(date +%F)`——**推荐 $() 写法**（可嵌套、可读性好） |

### 2. 特殊变量（面试必考，背表）

| 变量 | 含义 |
|---|---|
| `$0` | 脚本名 |
| `$1`…`$9` | 第 1~9 个参数 |
| `$#` | 参数个数 |
| `$@` | 所有参数（**保留独立性**，加引号后每个参数是独立个体） |
| `$*` | 所有参数（**合并成一个字符串**） |
| `$?` | **上一条命令的退出码**（0=成功，非0=失败）——脚本里判断成败全靠它 |
| `$$` | 当前进程 PID |
| `$!` | 最后一个后台进程 PID |

> `$@` vs `$*` 经典演示（务必自己做）：加引号时 `"$@"` 能正确处理带空格参数，`"$*"` 会把所有参数粘成一个。

### 3. 退出码 `$?` —— 脚本的"判断依据"

```bash
ls /notexist
echo $?        # 非 0（失败）
ls /etc
echo $?        # 0（成功）
```
**运维脚本的本质**：几乎每个判断都基于 `$?` 或命令返回值。

### 4. 条件测试三种写法

```bash
test -f /etc/hosts        # 写法1：test
[ -f /etc/hosts ]         # 写法2：[]（注意括号内两侧必须有空格！）
[[ -f /etc/hosts ]]       # 写法3：[[]]（bash 增强，支持 && || 和正则 =~）
```

**文件测试符（背下来，RHCE 和面试都用）**：

| 符号 | 含义 | 符号 | 含义 |
|---|---|---|---|
| `-e` | 存在 | `-f` | 是普通文件 |
| `-d` | 是目录 | `-L` | 是符号链接 |
| `-r` | 可读 | `-w` | 可写 |
| `-x` | 可执行 | `-s` | 存在且非空 |

**比较符（注意字符串与数字的符号不同！）**：

| 类型 | 等于 | 不等于 | 大于 | 小于 | 举例 |
|---|---|---|---|---|---|
| 数值 | `-eq` | `-ne` | `-gt` | `-lt` | `[ $a -gt 10 ]` |
| 字符串 | `=` | `!=` | `>` | `<` | `[ "$a" = "yes" ]` |

> ⚠️ 数值比较用 `-eq` 系列，字符串用 `=` —— 混用是新手第一大坑。

### 5. if / case 语法骨架

```bash
# if 骨架
if [ 条件 ]; then
    命令
elif [ 条件 ]; then
    命令
else
    命令
fi

# case 骨架（多分支选值，比 if-elif 链清爽）
case "$1" in
    start)   echo "启动";;
    stop)    echo "停止";;
    restart) echo "重启";;
    *)       echo "用法: $0 {start|stop|restart}";;   # *) 是默认分支，必须有
esac
```

## 知识点补充：生产脚本三件套（面试加分）

```bash
#!/bin/bash
set -e    # 任何命令返回非 0 就退出脚本（防"错了还往下跑"）
set -u    # 使用未定义变量时报错退出（防变量名为空导致 rm -rf / 级灾难）
set -o pipefail   # 管道中任一命令失败则整条管道失败（默认只看最后一条）
# 通常合写：set -euo pipefail
```

## 自检区（做完题再看，别偷看）

<summary>点开看答案（先做完！）</summary>

**L01**：`$LOG_DIRs` 会被解析成变量 `LOG_DIRs`（不存在→空），正确写法 `${LOG_DIR}s`。
**L03**：双引号内 `!` 触发 history 展开报错；单引号字面化，正常输出。
**L04**：`"$@"` 输出 `[a b]` 和 `[c]`（两个独立参数）；`"$*"` 输出 `[a b c]`（粘成一个）。
**L08**：`-gt` 正确（数值）；`>` 在 `[ ]` 里是**重定向符号**，会把比较结果写进文件——这是灾难级坑。
**L09 参考**：
```bash
#!/bin/bash
set -euo pipefail
usage=$(df -h / | awk 'NR==2{print $5}' | tr -d '%')
if [ "$usage" -gt 80 ]; then
    echo "警告：根分区使用率 ${usage}%"
else
    echo "正常：使用率 ${usage}%"
fi
```
**L12 参考**：
```bash
#!/bin/bash
set -euo pipefail
LOG=/var/log/monitor.log
if pgrep -x nginx >/dev/null 2>&1; then
    echo "$(date '+%F %T') nginx 运行正常" >> "$LOG"
else
    echo "$(date '+%F %T') nginx 未运行，正在启动..." >> "$LOG"
    systemctl start nginx
fi
```
**L15 简写**：`if grep -q root /etc/passwd; then echo yes; fi`（if 直接吃命令的退出码）

**I03 答案要点**：`[[ ]]` 支持 `&&` `||`（`[ ]` 只能用 `-a` `-o`）、支持 `=~` 正则、`==` 支持通配、单词不加引号也不会被分词拆分。
**I09**：见上文"生产脚本三件套"。
