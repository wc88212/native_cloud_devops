## Q1 软链接和硬链接的区别？删除源文件后各自表现？

**学员原始答案（评级 ⭐⭐⭐⭐⭐）**：
> 硬链接是同一个 inode 的第二个名字，大小与源文件相同，删除源文件后不影响硬链接访问；软链接拥有独立 inode，内容是目标路径，本质是稳定的指针，删除源文件后访问软链接悬空报 no such file。

**修正后标准版（补两个加分点）**：
- 硬链接：同一 inode 的第二个目录项，**不能跨文件系统、不能链接目录**（inode 号只在自家文件系统内唯一）。
- 删除源文件后硬链接可访问的机制：inode 有**引用计数**，`ls -li` 可见链接数从 2 变 1，**计数归零数据块才被回收**（实验已验证）。
- 软链接：独立 inode 的特殊文件，**内容是目标路径字符串**（`readlink` 可见），删除源文件后悬空。
- 应用场景一句话：软链接 = 稳定入口，用于版本切换（`/opt/app/current -> v1.1`）、多版本共存一个入口（python3）、跨位置引用。

**面试官追问预案**：
- 悬空链接怎么排查？→ `ls -l` / `readlink` 看指向，再看目标为何不存在（学员有亲身案例：`v1,0` 逗号错字）
- 为什么硬链接不能链目录？→ 会造成目录树成环，文件系统拒绝（`.`/`..` 已是特殊硬链接）

## Q2 find -mtime +7 和 -7 的区别？

**学员原始答案（评级 ⭐⭐⭐）**：七天以上 / 七天以内。

**修正后标准版（三要素齐全）**：
- `-mtime` 按**内容修改时间**，单位天；`+7` = 7 天之前（第 8 天起算），`-7` = 7 天之内；恰好第 7 天写 `7`（少用）。
- 分钟级变体 `-mmin`：`-mmin -60` = 最近 1 小时内动过的文件（排查"刚才谁改了文件"神器）。

## Q3 find -exec 里的 {} 和 \; 是什么意思？

**学员未答，标准版**：
- `{}` 是**占位符**：find 每找到一个文件，把文件名填到 `{}` 的位置执行一次命令。
- `\;` 是 **-exec 命令的结束符**：find 需要知道命令到哪结束；`;` 是 shell 特殊字符，不转义会被 shell 先解析掉，所以要写 `\;`。
- `+` 结尾不用转义，因为 `+` 不是 shell 特殊字符。

## Q4 磁盘满了如何定位大文件？（高频大题，背五步结构）

**学员原始答案（评级 ⭐⭐⭐，缺根因判断与预防）**：df -h → du -sh。

**修正后标准版（总-分-总，90 秒版）**：

1. **确认**：`df -h` 锁定哪个分区满、挂载点是什么
2. **定位**：`du -xsh` 逐层下钻（`-x` 不跨文件系统），或 `find / -xdev -size +100M` 直接揪大文件
3. **根因判断（段位分水岭）**：du 与 df **对不上** → 存在"已删除但仍被进程占用"的文件 → `lsof +L1`（或 `lsof | grep deleted`）找持句柄进程。典型场景：日志被 rm 但服务还开着句柄，空间不释放
4. **处理**：日志用 `truncate -s 0 文件` 清空而**不是 rm**（句柄还被占用时 rm 不释放空间）；或重载/重启占用进程；业务数据先评估再清理，必要时 LVM 在线扩容
5. **预防**：logrotate 轮转、监控 80% 水位告警、大文件目录独立分区

**收尾金句**："我实际处理过 du/df 不一致的情况，用 lsof 定位到 deleted 文件后重载服务释放的空间。"（W6 做完该实验即为真实经历）

## Q5 -exec {} \;、-exec {} +、xargs 的区别与选型？

**学员结论（基本正确，决策表修正后）**：

| | `-exec {} \;` | `-exec {} +` | `xargs` |
|---|---|---|---|
| 执行方式 | 每文件起 1 条命令 | 攒批起命令 | 攒批起命令 |
| 文件名带空格 | ✅ 安全 | ✅ 安全 | ❌ 需 `-print0 \| xargs -0` |
| `{}` 位置 | 任意 | **只能最末尾** | 任意（`-I{}` 自定义） |
| 独有能力 | — | — | 并行 `-P4`、串复杂管道 |

**选型决策（背这个）**：
- 默认批量处理 → `-exec {} +`（最稳：安全 + 快，不依赖外部工具）
- `{}` 不在末尾（如 `cp {} /backup/`）→ `\;` 或 xargs
- 需要并行 / 结果接着进管道 → xargs
- 文件名可能有空格且用 xargs → 必须 `-print0 \| xargs -0`

**速度差异的真相**：100 个文件 + rm 秒完测不出差异；**几千上万文件或单命令很慢**（如逐文件 ssh）时，`\;` 起一万个进程 vs `+` 起几个进程，差数量级。`{} +` 与 xargs 速度基本无差。
