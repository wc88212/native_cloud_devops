## 一、grep 三兄弟（本日重修点：D3 面试题 Q2 答错）

| | 正则引擎 | 特性 | 使用场景 |
|---|---|---|---|
| `grep` | 基础正则 BRE | `\|` `\(\)` 需转义才生效 | 简单字符串匹配 |
| `grep -E` | 扩展正则 ERE | `|` `()` `+` `?` `{n,m}` 直接用 | **日常主力** |
| `grep -F` | 无正则 | **Fixed 纯字符串**，`$` `.` `*` 全部字面化 | 搜索内容本身含特殊字符（如 `${PATH}`） |

**⚠️ 撞名警告**：`grep -F` ≠ `awk -F`（后者是指定分隔符）。记忆：E=Extended，F=Fixed。

## 二、高频六选项

`-v` 反向 / `-n` 行号 / `-c` 计数 / `-i` 忽略大小写 / `-r` 递归 / `-o` 只输出匹配部分

**"配置文件有效行查看器"**（面试满分答案）：

```bash
grep -vE '^\s*(#|$)' /etc/ssh/sshd_config
# ^\s*   行首任意空白
# (#|$)  注释符 或 行尾（空行）
```

对比 `grep -v '^#'`：只去注释，**空行还在**（面试官追问点）。

## 三、正则核心符号（亲手验证过）

| 符号 | 含义 |
|---|---|
| `.` | 任意单个字符 |
| `*` | 前一元素 0 次或多次 |
| `+` `?` | 1+/0-1 次（ERE） |
| `^` `$` | 行首 / 行尾锚点 |
| `[abc]` `[a-z]` | 字符集 / 范围 |
| `[^abc]` | **否定集合**（^ 在集合内第一位） |
| `{n,m}` | 重复 n 到 m 次（ERE） |
| `()` `\|` | 分组 / 或（ERE） |

### 三个亲手踩出来的坑

**坑 1：`^` 双身份**
- 裸露在模式中 = 行首锚点
- 在 `[` 后第一位 = 否定集合
- 判定法则：看它是否被 `[` 紧跟在后

**坑 2：锚点丢失的静默后果**
```bash
grep -oE "[0-9.]+" access.log      # ❌ 无 ^：匹配行内所有数字串
                                    # 实测：21、2026、1.1 各出现 N 次（每行都有）
grep -oE "^[0-9.]+" access.log     # ✅ 有 ^：只取行首 IP
```

**坑 3：`a*` 与 `.*`**
- `a*` = a 出现 0 次或多次 → **能匹配空串** → `grep "a*"` 输出所有行（每行都含 0 个 a）
- `.*` = 任意字符重复任意次 = 任意字符串（不是"单个字符重复"）

### "或"与"且"的写法（深夜答疑）

```bash
grep -E "^root|nologin$" /etc/passwd    # 或：| 优先级最低，切分整段
grep -E "^root.*nologin$" /etc/passwd   # 且：.* 串联两个条件（root 行 shell 是 bash，结果为 0 行）
```

### 定位第 N 列的通用套路

```bash
grep -E "^[^:]+:[^x]" /etc/passwd   # 跳过前1列 → 定位第2列（密码位）不是 x
# ^[^:]+  吃掉用户名（非冒号字符1+个）
# :       第一个冒号
# [^x]    密码位首字符不是 x（!、*、空 都是账号异常信号）
# 通用化：^[^:]+: 重复 N-1 次 = 跳过前 N-1 列
```
生产意义：**账号安全巡检**（密码位是 ! 或 * = 账户锁定/无密码）。

## 四、Shell 引用三剑客（W2 预习，本日已踩坑）

| 引用 | 效果 |
|---|---|
| `'单引号'` | **全部字面化**，最安全 |
| `"双引号"` | 保留 `$` `!` `` ` `` 的展开能力 |
| `\` | 只转义紧随的 1 个字符 |

**本日踩坑**：`echo "test2:!:1001..."` → `-bash: :1001: bad word specifier`
原因：双引号内 `!:` 触发 **history 展开**（`!:` = 取上条命令的第 N 个参数）。修复：改单引号。
规则：**含 `!` `$` 等特殊字符 → 一律单引号**。

## 五、结构化日志的选型结论（本日最有价值的认知）

| 工具 | 感知方式 | 适用 |
|---|---|---|
| grep | 字符模式，无字段概念 | 快速交互式找文本、找配置 |
| awk | **字段/列感知** | 结构化日志分析（IP=$1、状态码=$9） |

- `awk '$1'` 是**条件**（$1 非空则打印整行），取列必须 `awk '{print $1}'`
- 错误行：`awk '$9>=500 && $9<600'` 比 `grep ' (401|403|502) '` 精准（grep 的空格技巧无法防止字节数误判）
