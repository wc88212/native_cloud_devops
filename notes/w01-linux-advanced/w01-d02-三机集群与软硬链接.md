## 一、今日踩坑实录（按时间线）

### 坑 1：ln -s 打错一个字符 → 悬空链接静默生效
- **现象**：`ln -sfn /opt/app/v1,0 /opt/app/current` 后，cat/cd current 全部报"没有那个文件或目录"
- **根因**：把 `v1.0` 打成 `v1,0`（逗号）。**ln -s 不校验目标是否存在，创建"合法成功"**，坑是静默的
- **正确排查姿势**：软链接出问题，第一步 `ls -l` / `readlink` 看它指向谁，而不是反复 cat/cd
- **同类坑**：通配符不匹配时 shell 原样传字符串（W1-D1 的 Rocky-*.repo 案例）——**Linux 很多失败是静默的，验证习惯是唯一保险**

### 坑 2：xargs 遇到带空格文件名报错
- `touch "a b.txt"` 后 `find | xargs rm` 把 `a b.txt` 拆成两个参数
- 解法：`find -print0 | xargs -0`（用 \0 分隔符代替空白分隔）
- `\;` 和 `+` 形式不受影响（find 直接传参，不二次解析）

## 二、知识点沉淀

### 软硬链接（对照实验已验证）
| | 硬链接 | 软链接 |
|---|---|---|
| inode | 与源相同（`ls -li` 验证） | 独立 |
| 本质 | 同一 inode 的第二个名字 | 特殊文件，内容=目标路径字符串 |
| 删源文件后 | 不受影响（引用计数 2→1，归零才回收） | 悬空 |
| 跨文件系统/链目录 | ❌ / ❌ | ✅ / ✅ |
| 典型用途 | 备份保护（防误删） | 稳定入口：版本切换、多版本共存、跨位置引用 |

**一句话本质**：软链接 = 稳定的指针（统一入口）。版本切换器只是它的一种用法。
**注意**：软链接是 `l` 类型的**文件**，不是目录——`cd` 能进是因为内核顺着它存的路径跳转。

### 生产回滚模型（ln -sfn）
```bash
ln -sfn /opt/app/v1.0 /opt/app/current   # -n 是关键：防止把链接建进目录内部
```
发布/回滚 = 改指向，秒级完成。程序只认 `current` 这个固定入口。

### find 核心（条件 + 动作）
- 条件：`-name/-iname`、`-type f/d/l`、`-mtime +7/-7`（天）、`-mmin -60`（分钟）、`-size +100M`、`!` 取反
- 动作：`-delete`、`-exec {} \;`（逐个）、`-exec {} +`（攒批，{} 只能在末尾）、`-print -delete`（先确认再删）、`| xargs`（见坑 2）
- **生产习惯**：删除前先 `-print` 看清单，或先 `| wc -l` 数量确认
